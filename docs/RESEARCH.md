# Primary references and version choices

Reviewed 20 October 2026. Implementation uses installed versions, not assumed latest APIs.

- [dash.js ABR](https://dashif.org/dash.js/pages/usage/abr/) and [ABR settings/custom rules](https://dashif.org/dash.js/pages/usage/abr/settings.html): pin **5.0.3**; disable built-in rules for custom modes. Default combines throughput and BOLA.
- [v4→v5 migration](https://dashif.org/dash.js/pages/developers/migration-guides/4-to-5.html): representation APIs replace obsolete quality APIs. The npm package's `index.d.ts` and source-map `SwitchRequest.js`, `ThroughputRule.js`, `ABRRulesCollection.js` were inspected. `SwitchRequest.representation` is an actual Representation, not a quality index. `getRepresentationsByType('video')` supplies it. The ESM build doesn't export FactoryMaker as a named export; the shipped bundle initializes `window.dashjs.FactoryMaker`, which the custom factory uses. This was verified by real Chrome requests/decoding.
- [Throughput calculation](https://dashif.org/dash.js/pages/usage/abr/throughput-calculation.html), [BOLA](https://dashif.org/dash.js/pages/usage/abr/bola-rule.html), [official repository](https://github.com/Dash-Industry-Forum/dash.js): player-default estimates differ from our explicitly defined effective-request measurements. BOLA is context for the built-in baseline.
- Repeated-session verification found that `FactoryMaker.getClassFactory` caches by class name, which can retain a closure over an old session. The final custom-rule factory directly implements the shipped `rule(context).create()` protocol and creates fresh rule state for every player. `SwitchRequest` still comes from the player's actual factory. Fresh-browser-context evaluation was unaffected by the earlier lifecycle issue; the same-page sequence is verified separately.
- [FFmpeg DASH muxer](https://ffmpeg.org/ffmpeg-formats.html#dash-2): use adaptation sets, explicit initialization/media templates and segment timeline. H.264 GOP=48 at 24 fps, no scene-cut GOP changes, two-second forced keyframes. Working directory is the media directory, avoiding Windows absolute output-path handling differences. Exact encoder version is recorded by doctor and media configuration.
- [FastAPI streaming](https://fastapi.tiangolo.com/advanced/stream-data/): installed **0.115.5** uses explicit StreamingResponse with an async byte generator, not newer framework return-type conveniences. Uvicorn **0.32.0**.
- [Resource Timing](https://developer.mozilla.org/en-US/docs/Web/API/PerformanceResourceTiming): same-origin encodedBodySize and timing, no cache or cross-origin missing-size assumptions. Observer filters actual video fragments.
- [RandomForestRegressor](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.RandomForestRegressor.html): installed **1.5.2**; standard fitted tree arrays are exported. Float32 input conversion and exact threshold direction are tested across Python/TypeScript. No arbitrary pickle uploads.
- [Playwright browsers/media codecs](https://playwright.dev/docs/browsers): **1.56.0**, installed Chrome channel. H.264/AAC support must be tested with real decode progress; bundled Chromium availability is not assumed.
- [Reduced motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion): remove decorative transition/tilt under reduced-motion and benchmark settings.
- [Pensieve](https://web.mit.edu/pensieve/) and [Fugu/Puffer](https://www.usenix.org/conference/nsdi20/presentation/yan): background on learning-based adaptive streaming and measured evaluation. StallGuard is small supervised next-request regression, not a reproduction of reinforcement learning or in-situ Fugu deployment.

Frontend uses React **19.0.0**, TypeScript **5.7.3**, Vite **6.1.0**, Node **20.19.4**. All runtime assets are bundled locally; charts are small SVG paths to avoid another runtime library. No CDN fonts/assets. Dependencies are pinned for this tested build; this does not establish long-term support or absence of all dependency vulnerabilities.
