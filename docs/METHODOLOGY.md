# Methodology

> The original definitions below describe the historical experiment. The repaired audit uses `metric_version: audit-v2`: final stop samples, explicit decision IDs/epochs, transition media times, separate initial assignments, and a pause/seek-excluding ratio denominator. See AUDIT_REPORT.md for the exact changes and limits. Historical summaries/raw observations are preserved, not relabeled as v2 measurements.

Effective request throughput is `8 * encodedBodySize / (responseEnd - requestStart)` in bps with duration converted to seconds. Resource Timing includes first-byte latency, not just body transfer time. Only completed video media chunks enter features. Audio, init, manifest, zero/missing bytes, overlaps, and incomplete requests do not. All actual media payloads including repeated/init/audio transfers count in server delivery totals. Completed sequential replacement requests remain valid transfer samples because a real HTTP body was delivered; the target is a request, not a unique playback interval. Server records retain cancellation/repeated assets separately.

The five most recent throughputs, mean, population standard deviation, endpoint trend divided by four, last duration, last observed idle gap, and last body size form 11 features. No capacity/profile ID/seed/session identity or future size enters the feature vector. A row labels the next sequential completed video request, with its start no earlier than the previous completion. Window history resets per session. Browser/model inputs use the same order; tree thresholds compare float32 inputs (`Math.fround`) with `<=`. Trusted tree JSON is structurally validated before ML readiness. Five observations are needed for forest inference; cold start and missing models use EWMA with explicit labels.

Training/validation run definitions are in `scripts/experiments.py`. They are split by entire session before fitting, use distinct profile parameters and seeds, and never mix final test rows into training. Stable traces must differ by scale; a different seed alone would not change their capacity. The initial forest settings are fixed (32 trees, depth 6, min leaf 3, seed 731), with no data-dependent transforms or parameter search. Validation is reported but not used to manufacture a better result. The final unfamiliar profile is absent from training/validation.

Both custom controllers use identical parameters: forecast × 0.8, minus 80 kbps audio/protocol reserve, then a sustainable manifest bitrate. Buffer below four seconds forces the lowest representation. Downgrades are immediate; upgrades require two new observation boundaries and move at most one representation. Repeated rule calls do not advance hysteresis. No candidate size estimate is used. Cold start uses the lowest representation. Default mode is called **dash.js default**, which combines BOLA/throughput and auxiliary rules; it is not a pure historical estimator.

A decision at history boundary n links to request n only if the decision timestamp precedes that request's start. Prediction error excludes late/unmatched forecasts. Charts show forecasts paired at target completion; they do not shift a prediction back from a future observation. All segment/decision raw times remain available. Requests can have different sizes and idle gaps, so effective throughput is not perfect physical capacity knowledge. Reported model errors compare the next-request target, not configured capacity.

Startup is play intent → first native `playing`. A single deduplicated state machine opens rebuffering only after startup when `waiting` occurs with playable buffer below 0.25 s. Repeated waiting does not duplicate a stall. Resume, pause, seek, end, or error closes the interval. Deliberate pause/seek is excluded, and waiting with nonempty buffer is not counted as a network stall. This cannot diagnose every decode/render issue; browser errors are separate. Rebuffer ratio denominator is elapsed wall time from first playing to final observed event, including pauses; benchmark runs contain no manual pauses. Bitrate is duration-weighted from rendered representation events using forward media-time progress between ~1 Hz samples. This has approximately one-second transition resolution. Switch count/magnitude use rendered changes. It is not perceptual quality.

Controlled experiments run one browser context at a time, same viewport, no-store media, fresh UUID/player/context, the same quiet visuals/buffer settings, and no competing playback. The ending rule is fixed wall clock after `start` returns (model load precedes media clock). A stopped bounded experiment is a completed run, but is not full-video evidence. Requests in flight at the ending boundary are cancelled, retained in server records, and counted as cancellation/failure rather than silently dropped. `delivery_failures` therefore includes intentional end-of-run aborts; it is not exclusively network failures.

The profile clock starts with the first non-manifest body, follows elapsed experiment time including stalls and user pauses, and never resets during a run. Profiles are synthetic deterministic delivery-capacity signals. Stable is 3.5 Mbps; step drops to 0.48 Mbps at 12 s and recovers at 28 s. Scale is bounded to [0.2,3], actual capacity [0.1,20] Mbps. Outages/zero capacity are not supported. A small credit bound accommodates local timer granularity; calibration must pass <15% aggregate error before collection.

Use MAE/RMSE, sample counts, startup, stalls, rendered bitrate, switching, latency, and bytes together. No composite QoE score, MAPE, fabricated accuracy percentage, or guaranteed ML improvement is used. A single repetition provides no reliable variance estimate; more independent repetitions/full-duration clips are the first extension.

Sessions also carry a hash of the actual encoded init/media bodies. Comparison warns when media fingerprints differ, even if the asset ID/ladder name is unchanged. The evaluated media inventory/hashes were preserved before a later preparation rerun; re-encoding was not byte-identical. All controlled matrix runs used one fixed original preparation. A new preparation requires a new matched matrix; old/new single runs are not automatically equivalent.

HTML media buffered ranges can report near-zero intersection while already decoded media continues advancing. Zero on the buffer plot alone is not counted as a stall: a post-start native waiting interval is required. Full default/custom ABR and buffer settings are retained in final configuration events and `data/results/player-settings.json`; earlier matrix events retained a truncated settings description and the pinned configuration source remains available.
